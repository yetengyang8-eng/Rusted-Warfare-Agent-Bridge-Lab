## 本轮唯一目标
实现“固定条件 A/B 对比能力 v0”：同一候选、同一地图/难度/倍速/时限下，两个并行 episode 可以使用不同的既有实验配置，并能跨批汇总比较。

### 1. per-instance profile
- 为并行 pair 支持 A/B 两个独立 profile；建议 JSON 或等价显式配置文件。
- profile **只允许覆盖现有、已允许实验的 `-Drwagent.*` 旋钮**；不得通过 profile 新增策略逻辑。
- 至少先支持当前明确实验旋钮，例如 `mobileUnitHardCap`；其他字段做白名单，不要任意透传 JVM 属性。
- 每个 episode 必须把 profile 名、规范化内容、profile SHA/digest、实际传入的 JVM 属性写入 `episode.json` / `batch.json` 及可追溯证据。
### 2. v0 不碰 seed 内部写入
- `runtime.json` 可记录实际 seed，但 `seedReproducibilityVerified=false`；本轮不要写引擎内部状态、不要重开 Lab。
- A/B 用重复 N 局处理随机性；保存每局实际 seed、结果和原始证据。
- 为抵消 episode/启动顺序偏差，批次必须支持 A/B 位置交叉：一批 ep1=A/ep2=B，下一批 ep1=B/ep2=A，或等价的自动平衡方案。

### 3. 跨批聚合器
- 新增只读聚合能力，不改策略：按 profile 汇总完成率/胜负、游戏时长、产兵、损失、支出、矿/厂、关键经济事件等现有报告字段。
- 至少输出样本数、均值/中位数、离散度（标准差或分位数）和每局原始 report/run 索引。
- **不要输出“哪个策略更好”的硬编码评分或自动裁决**；保留原始指标供后续分析。
- 必须校验候选 contentDigest、地图/难度/倍速/时限等条件一致；不一致时拒绝合并或明确分组。
