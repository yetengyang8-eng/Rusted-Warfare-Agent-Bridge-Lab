# 0.03-alpha2 修复说明

两次0.03-alpha1开局均在规划阶段失败，没有下令。原版内置抽取器并非旧 Java 枚举 extractor，而是覆盖它的 extractorT1。这是桥接层遗漏，不是用户需要换模式或多试几次。

修复包括：

- 抽取器、工厂、坦克统一调用引擎替换表，按真实类型对象匹配菜单动作。
- 建筑候选模板按真实元数据创建，extractorT1 使用真正 custom.j 模板及单格占地；预览不会注册进世界表。
- 客户端用计划中的 extractorType/factoryType 识别完工，检查命令回执类型；不再硬编码建筑类型。
- 找不到矿时输出实际类型、合格建造者数量、当前可见资源候选数，减少盲目重测。

验证：同一原版替换夹具使旧JAR在 /opening/plan 复现用户的409，新JAR通过。覆盖旧枚举和 extractorT1 两条原生对象路径；HTTP客户端默认以 extractorT1 推进完整五单开局，并保留旧类型回退及预算/死亡/换局/干扰测试。详细输出见 test-results.txt、regression-opening-alpha1.txt。

这些检查未运行完整游戏寻路和世界模拟。实机只需重启并运行一次 RW-Agent-Opening.bat；成功标准仍为2栋新建筑、3辆不同ID的新坦克、5次成功下令。已通过的往返和单厂单坦克无需单独重测。
