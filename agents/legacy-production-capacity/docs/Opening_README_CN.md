# Rusted Warfare Agent：Opening 使用说明（保留入口）

修复上版两次在规划阶段零下令的问题：原版抽取器实际为 `extractorT1`，上版遗漏了内置单位替换。现在规划、占地模板、建造指令及完工验收均跟随实际类型；旧版问题已在原版对象回归中复现。

本轮基础开局流程：**自动选择附近矿点 → 建抽取器 → 建陆军工厂 → 连续生产并确认 3 辆坦克**。

资金不足时先等待收入；每一步观察实际结果后才推进下一步。所有建筑与坦克走原生命令，不直接生成单位或改钱。

已通过的底座：0.01-alpha2 移动往返；0.02-alpha2 建厂出兵，实机报告 PASS、2 次下令、55 次观测、26.726 秒。0.03-alpha2 完整开局已通过实机验收。

## 只测这一局

1. 关闭游戏，把包内 `rw-agent-bootstrap.jar` 和全部 `RW-Agent-*.bat` 覆盖到之前成功的原版 PC 1.15 游戏目录。无需另装 Java/Python。
2. 用 `RW-Agent-Start.bat` 启动。沿用无敌军干扰的本地单人遭遇战，使用**普通建造者**，附近须有当前可见、未占用的矿点和工厂空地。普通 4000 开局资金即可，留出 3 辆坦克的人口空间。
3. 双击 **`RW-Agent-Opening.bat`**。不需要手动指定坐标或鼠标选中建造者。它会在支持建矿与建厂的己方建造者中选择最近的合法矿点。
4. 保持正常速度、不暂停，不开启瞬间建造，不手动指挥相关单位，也不让其他工厂同时生产坦克。只运行一个控制脚本。
5. 等待窗口显示 `PASS` 或 `FAIL`，把 `rw-agent-reports` 内本次 **`opening-….jsonl`** 发回来。失败再附 `rw-agent-bootstrap.log`、`rw-agent-game.log`。

成功的报告应包含：2 栋新建筑完成、3 个不同 ID 的新坦克、5 次成功下令。最后再次确认建造者、两栋建筑及三辆坦克仍存活。已通过的往返和单厂单坦克不需要单独重测。

可选指定建造者：在游戏目录命令提示符运行 `RW-Agent-Opening.bat 单位ID`。例如 ID 必须从本局 State 读取，不能照抄旧局。

## 过程与停止条件

| 阶段 | 行为 |
|---|---|
| 规划 | 在建造者 600 世界单位内寻找当前可见矿点，检查完整占地和原生合法性，选直线距离最近者 |
| 抽取器 | 等足 700 资金再下单，确认新抽取器完工 |
| 工厂 | 为兼容已通过接口，先等足工厂加一辆坦克的预算（原版 1050）；再按建造者当前位置重新选附近工厂空地并建造 |
| 坦克 1–3 | 各自等待资金；每次只下一辆，观察队列从有任务到空以及新坦克出现，再进入下一辆 |
| 结束 | 报告实际完成数，成功才输出 PASS；不继续无限出兵 |

原版总支出是 700 + 700 + 3×350 = 2450，过程中可以有自然收入，所以不要求开始时一次持有全部预算。

每次资金等待最多 120 秒；每栋建筑最多等 240 秒；每辆坦克最多等 120 秒；整个任务最多 600 秒。连续 10 秒帧号不推进会停止。资金/地形/存活情况会在下令或观察时再检查。

矿点不可见、被占用、没有合格建造者时，规划拒绝且零下令。脚本不自动去未知区域探矿。600 是直线候选距离，尚未验证完整行走路径，也没有敌军威胁评估；这一轮仍需无敌军干扰的环境。

建造者、已完成的任务建筑或已确认的坦克死亡/消失，换局，队列混入其他任务，或接口出错，都会停止并写明阶段。503 表示结果可能未知，不自动重试。关闭脚本或 Ctrl+C 只停止后续下令，游戏内已提交命令继续执行；需要自行取消。没有最终 summary 的报告按中断处理。

再次运行会尝试新建一套，不会接着上次续跑，也不会把既有建筑/坦克计入成功。单位归因仍依靠新 ID、位置与队列变化，因此测试期间不要并行生产或建造。
