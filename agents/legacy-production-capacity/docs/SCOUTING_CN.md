# 0.06 自主侦察、扩矿与护卫

这一版把 0.05 的可见矿位扩张接到自主侦察上。缺少合法矿位时，Agent 会选择探索方向、等待坦克护卫靠近、移动建造者、观察新视野，再尝试建矿。工厂继续独立生产。

## 使用

1. 退出旧版游戏，将升级包内的文件覆盖到已有游戏目录，与 `game-lib.jar` 同级。
2. 用 `RW-Agent-Start.bat` 启动游戏。先选择标准单位、1 对 1、正常迷雾的本地遭遇战。建议首先复现 **Ice Island (2p)**。
3. 游戏开始后双击 `RW-Agent-Autopilot.bat`。双击默认目标为发展阶段新增 8 辆坦克、2 座矿，最多 24 次探索移动。
4. 等控制窗口输出 PASS、PARTIAL 或 FAIL，再运行 `RW-Agent-Collect-Reports.bat`，发回 `report-bundles` 中生成的 ZIP。

已有空闲陆军工厂时会直接复用；没有工厂时先建厂并验证生产 1 辆坦克，再进入发展阶段。因此全新开局的默认总产出目标是 **1 厂、2 矿、9 辆坦克**，其中 1 辆属于建厂验证阶段。程序不会主动出售、删除或替换原有单位。

双击入口采用较短的 2 矿目标。3 矿是进阶目标，仍可能遇到无法处理的战斗压力；本轮交付保留了成功、部分完成和失败的完整记录。Java 客户端和后台实验的无参数默认矿目标仍为 3，复现双击入口时显式传入 `--mines 2`。

可在命令提示符中指定目标：

```bat
RW-Agent-Autopilot.bat 8 3 24
RW-Agent-Explore.bat 8 2 16
```

参数顺序是新坦克数量、新矿数量、探索移动上限。范围分别为 1–30、0–10、1–48。`Explore` 要求已有已完成且空闲的陆军工厂。`Develop` 仍然保持旧版的“仅使用当前可见矿位”行为。

## 观察边界

- 资源只在当前可见时读取。建矿要求整个占地当前可见、原生建造检查通过，并且在建造者可达范围内。
- 路径先查询可见性，再读取原生移动代价。重新进入迷雾的旧路只能使用先前观察到的通行记录；不会读取隐藏区域的新状态。
- `pathKnown=true` 表示路径由当前可见或曾观察过的地块组成；`pathVisible` 单独表示整条路径是否此刻仍可见。记忆可能过时，实际行走失败会触发停滞检查。
- 敌军信息只在原生可见性检查通过后读取。失去视野后只保留最后观察的位置；移动威胁记忆最长保留 20 秒游戏时间，已知建筑可保留至其位置重新可见并确认空缺。
- 单局地图或玩家改变、帧号倒退时清空记忆和旧指令回执。控制只允许本地非联网、非录像的己方单位。

## 护卫与风险响应

最先生产的至多 3 辆坦克收到游戏原生 `guard` 指令。报告只有在己方单位状态中实际观察到护卫指令和正确的建造者 ID 后才计为确认。探索开始前至少等待 2 辆护卫靠近；坦克目标为 1 时等待 1 辆。

建造者遇到附近可见武装敌军或生命低于 85% 时，会尝试回到本轮首次选中它的位置。威胁检查覆盖移动、等待和扩矿施工；必要时中断未完成的建造，未完工矿不会算作成果。撤回失败、护卫集结超时或探索次数用尽会有明确终止原因。

护卫单位的跟随、射击、选敌由原生游戏逻辑执行。目前没有专门的战斗微操、反空军编成、维修恢复或主动攻城策略。基础坦克无法解决所有威胁，单位可能阵亡。

## 结果定义

| 结果 | 含义 |
| --- | --- |
| PASS | 新坦克与新矿两个目标均达成，任务要求的单位在最后观测中存活 |
| PARTIAL | 坦克目标达成，但扩矿因可达性、威胁或探索上限等有界条件提前结束 |
| FAIL | 指令或状态异常、超时、换局、任务单位死亡等导致中止 |
| INVALID | 离线分析发现报告截断、计数矛盾或缺少必要的观测证据 |

这些结果衡量有界经济任务，不表示赢下一场对局。游戏暂停超过 10 秒、用户同时操纵受控单位或改动工厂队列，都可能中止任务。不要同时运行两个控制脚本。

## 复现实验

安装 Python 3 后，在已组装游戏目录执行：

```bat
RW-Agent-Headless.bat --mode autopilot --map "maps/skirmish/[p2]Ice Island (2p).tmx" --speed 1 --timeout 360
RW-Agent-Headless.bat --mode frontier --map "maps/skirmish/[p2]Ice Island (2p).tmx" --episodes 2 --speed 4 --timeout 200
```

每局独立目录、端口和原版引擎进程。不会复制用户存档、录像、偏好或外部模组。后台模式关闭画面与声音，但使用原版地图、资源、寻路、单位更新、资金及生产逻辑。它不能替代 Windows 图形界面的实际验收。

桌面轮询间隔默认 500 毫秒；后台探索模式按请求的加速倍率缩短到至少 100 毫秒，尽量维持相近的游戏内反应间隔。报告保留现实时间与游戏帧数。随机种子有记录，未证明跨进程完全可复现。

## 新增接口与证据

| 接口 | 用途 |
| --- | --- |
| GET `/scout/observe` | 视野计数、已观察资源、当前可见武装威胁及最后观察记忆 |
| GET `/scout/plan` | 可选 `unitId`、`avoid`，返回有限探索路径；不会下发移动 |
| GET `/expansion/plan` | 在旧开局规划基础上增加当前可见路径和威胁范围过滤 |
| POST `/command/guard` | `unitId,targetId,sessionId,requestId`；仅己方已完成武装移动单位护卫己方目标 |
| GET `/state` 新字段 | 己方单位的 `orderType`、`guardTargetId`；不会输出敌方指令目标 ID |

`frontier-*.jsonl` 记录视野、探索路径、指令回执、位移到达、资源首次发现、护卫确认和建筑完成。`scoutedMines` 需要“初始观测中不存在 → 探索移动期间首次可见 → 新矿完工”的完整链条；仅发现资源或下发建造命令不计入。

报告分析器同时保留旧版报告兼容性。新收集脚本只收集 `rw-agent-reports` 下的 JSONL 报告和离线汇总，并附校验值，不打包游戏资产和存档。
