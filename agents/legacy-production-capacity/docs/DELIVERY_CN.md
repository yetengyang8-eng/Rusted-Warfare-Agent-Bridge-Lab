## 本轮结果

用户发来的 0.06 报告满足预期。附件虽然带 `.zip.partial` 后缀，但 ZIP 的 36 项内容 CRC 通过，35 个清单项逐个 SHA256 一致；程序指纹与交付版完全匹配。32 份报告中本次新增的两份均 PASS：1 工厂、2 矿、9 新坦克；其中一座矿通过自主侦察发现，5 次侦察到达、3 辆护卫的真实 guard 订单获确认，新观察 2140 格。其余 30 份是历史报告，不能拿来算本次通过率。

在这个基础上，本轮完成了 **从标准开局到原生胜负结算的规则对战原型**。新增原生整队进攻、可见敌军及最后见到的位置记忆、工厂 T2 升级、普通/重型坦克持续生产、战损后继续作战、残血撤回尝试、统一的战斗命令间隔，以及可离线播放的战术日志视图。

## 怎样使用

先退出旧版游戏，将包内文件覆盖到游戏目录。运行 `RW-Agent-Start.bat`，创建本地原版 1v1 遭遇战，开启正常迷雾，然后运行 **`RW-Agent-Match.bat`**。保持对局运行，不同时手动操纵单位或运行其他控制器。

Match 从新开局建厂，完成最多一座当前可见矿及七辆坦克后进入战斗。已有闲置工厂则直接进入战斗。战斗默认最多 900 游戏秒；`RW-Agent-Match.bat 1800` 可延长到 1800 游戏秒。

结束后运行 **`RW-Agent-Collect-Reports.bat`**，发送它提示的完整 ZIP。资料目前已经足够继续开发，无需重新提供游戏安装包。下一份最有价值的反馈，是这个新入口在用户 Windows 游戏中的原始报告；本轮新增对战功能尚未经用户的 Windows 窗口实测。

`PASS / VICTORY` 才是胜利；`PASS / DEFEAT` 是有效完整败局；`PARTIAL / ONGOING` 是时限到了仍在进行；`INVALID` 是证据不完整。批量工具分别统计这些结果，不将所有 PASS 当胜利。

旧的 `RW-Agent-Autopilot.bat` 仍用于 8 新坦克、2 新矿的侦察扩张验收。直接战斗用 `RW-Agent-Battle.bat`。回退包位于 `rollback/Rusted-Warfare-Agent-0.06-Upgrade.zip`。

## 验证和工程修复

最终回归通过：**88 项 Python 测试、13 轮 Java 检查**。重新构建的 JAR 与实际交付 JAR 的全部 54 个归档项内容一致，仅构建时间等 ZIP 元数据可能不同。

专门验证了隐藏敌军不暴露、隐藏期间不刷新位置/血量、整队指令重试与拒绝条件、原生 attackMove 执行、升级计入完整队列、原生结算标志、虚假战术证据拒绝、升级预算饥饿和军队上限下仍可升级。

报告现在保留有界提交快照，在结束时一次性写新文件并同步、原子改名。故障模拟验证：即使进行中的日志路径被旧内容替换，最终封存仍包含完整 UTF-8 内容与结尾。收集器改为同步写句柄，完整 `.zip.partial` 可经 CRC、SHA256 和报告数量验证后恢复；没有在 Windows 重现旧 ZIP 未改名的具体异常，因此不推断其唯一原因。

日志视图的导出、拖动、播放和不同画布尺寸已检查，并渲染查看了实际画布；当前环境缺少 Chromium，未做完整浏览器排版验收。

## 距离最终目标

原方案的 **0.1 完整对局原型已经出现**；0.3 所需的侦察、扩张和基础战术有部分组件，但尚需统一成稳定策略。0.5 的跨图强度及真人水平没有证据；0.7 的真人回放学习、0.8 的竞技验证和 0.9 的自我博弈成长尚未实现。

下一步应先做 Windows 新入口验收、九图重复评测、持续经济与战斗协同、损失恢复/修理/防空和全局 APM/反应约束，再建立学习循环。本版没有神经网络，运行次数增加本身不会让它自动变强。不用软件版本号推算项目完成百分比或剩余工期。
